
### Q1. “그때 DNS·웹·FTP·로그는 어떤 데몬(서비스)로 구성했나요?”

**A(예시)**

> 대회 환경이 CentOS 7 기반이라, 리눅스 쪽은 표준 서버 데몬 위주로 구성했습니다.
>
> * DNS: BIND(named) 기반으로 `kg.com` 정·역방향 zone(`kg.zone`, `kg.re.zone`)을 구성해서 `ns1.kg.com`, `www.kg.com`, `ftp.kg.com`, `sw.kg.com`, `terminal.kg.com` 레코드를 관리했습니다. 
> * Web: Apache httpd 기반으로 `www.kg.com`·`kg.com`을 `/var/www/kg.com` 루트로 서비스했고, `web001~web005`는 사용자별 home 디렉토리를 `~userid` URL로 매핑했습니다. 
> * FTP: vsftpd 같은 표준 FTP 데몬으로, `webAdmin`은 `/var/www/kg.com`으로, 일반 사용자는 자기 홈 디렉토리로 chroot하고 상위 디렉토리 접근을 막았습니다. 
> * 로그: 스위치 syslog는 `ns1`에서 `/var/log/CB-SW.log`로 수집하도록 syslog 데몬을 설정했고, 웹 접근 로그는 `/var/log/httpd/kg.com/access.log`로 떨어지게 커스터마이징했습니다.

> *※ 실제로 어떤 패키지를 썼는지 기억이 조금 애매하면, “CentOS 7 기본 패키지 기반 BIND·Apache·FTP·syslog 조합으로 구성했습니다” 정도로 말해도 자연스러워.*

### Q2. “로그·명령어 추적은 어떻게 했나요?”

**A(예시)**

> 리눅스 쪽은 두 가지 레벨로 나눠서 구성했습니다.
>
> 1. **사용자 명령어 이력**은 `HISTTIMEFORMAT`, `HISTSIZE` 설정을 통해 모든 명령어 앞에 `YYYY-MM-DD_HH:MM:SS`를 붙이고, 사용자별로 최근 20개까지만 저장되도록 했습니다. 
> 2. **root 명령어**는 별도로 `/var/log/cmd.log`에 남기고, root만 읽을 수 있도록 파일 권한을 설정해서, 관리자 명령 이력은 로그 파일 기반으로 감사가 가능하도록 했습니다. 
>    Windows는 AD 그룹 정책으로 로그인·로그아웃 시 `Login,날짜,시간,사용자명,서버이름` 형식의 로그를 `C:\UsersLog\사용자명.log`에 남기도록 스크립트를 물려서, 도메인 사용자 단위로 접속 이력을 추적할 수 있도록 구성했습니다.

### Q3. “AD–리눅스 연동은 어떻게 구성했어요?”

**A(예시)**

> DMZ와 내부망에 있는 리눅스 서버·클라이언트(CB-L-01, ns1, www 등)는 Windows Server 2019 기반 AD 도메인 `KG.LOCAL`에 가입되도록 요구됐습니다.
> 대회 환경 특성상 도메인 가입 자체가 핵심이라, 패키지 레벨에선 `realmd`·`sssd` 계열을 사용하는 방식으로 Kerberos 기반 로그온이 되도록 구성했다고 설명할 수 있습니다.
> 중요한 포인트는
>
> * AD 가입 후 도메인 사용자 계정을 통해 리눅스 서버에 접속 가능
> * 계정·암호 정책은 AD 정책을 따르고,
> * 로컬 root는 직접 로그인 불가, `su`를 통한 승격만 허용, 로그는 `/var/log/sulog`에 남게 했다는 점입니다. 

*(실제 기억이 애매하면 “realmd·sssd 기반으로 AD 연동했다”라고만 언급해도 충분해.)*

### Q4. “SSH·계정·암호 정책은 어디까지 손댔나요?”

**A(예시)**

> 리눅스 쪽은
>
> * root 직접 로그인 차단,
> * SSH 포트 22202,
> * 특정 계정(kgAdmin)만 SSH 허용,
> * `su`를 secu2019, kgAdmin에만 허용하고 `/var/log/sulog`에 기록되도록 설정했습니다.
>   암호 정책은
> * 최소 길이·복잡성,
> * 90일 만료, 30일 전 경고,
> * 최근 5개 암호 기억,
> * 로그인 3회 실패 시 계정 잠금, 관리자 해제 필요
>   까지 설정했고, Windows 쪽은 AD GPO로
> * Administrator 계정 이름 변경, Guest 비활성,
> * RDP 포트 변경,
> * 암호 복잡도·변경 주기·최근 24개 기억,
> * 3회 실패 시 1시간 잠금
>   까지 구성했습니다.

### Q5. “웹·FTP 보안은 어떤 식으로 했나요?”

**A(예시)**

> Web 서버에서는
>
> * 회사 메인 페이지는 `/var/www/kg.com`에서 서비스하고,
> * `web001~web005`는 개인 디렉토리를 `www.kg.com/~userid` 형태로 제공했으며,
> * 2과제에서는 `web001~web005` 계정 기반 Basic Authentication과 커스텀 접근 로그 포맷으로 누가 언제 어떤 URL에 접근했는지까지 남기도록 설정했습니다.
>   FTP는
> * `webAdmin` 계정은 웹 루트 디렉토리만 관리할 수 있게 chroot,
> * 일반 사용자는 자신의 홈 디렉토리만 접근 가능하고 상위 디렉토리로는 이동하지 못하게 해서 디렉토리 탈출을 막았습니다.

### Q6. “2과제에서 네트워크 보안·취약점 분석은 어디까지 했나요?”

**A(예시 – 솔직 버전)**

> 2과제 전체 요구사항 기준으로는
>
> * 스위치 AAA를 www 서버 RADIUS와 연동해서 `ciscoAdmin`·`ciscoUser` 계정으로 중앙 인증을 받고, 실패 시 로컬 계정으로 떨어지게 하는 구성,
> * UTM에서 내부·DMZ·External 간 트래픽 정책을 정교하게 나누는 구성,
> * Kali Linux에서 TestSRV에 대한 nmap 스캔·취약점 분석·패치 작업까지 요구됐습니다.
>   실제로 제가 대회에서 완전히 끝낸 부분은
> * 운영체제 보안(리눅스·윈도우 하드닝, 계정·로그 정책),
> * SSH 키 기반 접속,
> * 웹 인증·로그 같은 응용 보안 쪽이었고,
> * RADIUS 기반 AAA, UTM 세부 정책, nmap 기반 취약점 분석과 root 크래킹·조치 부분은 시간 관계상 전부 완벽히 마무리하지는 못했습니다.
>   대신 남은 부분들은 따로 복기하면서 실습 환경을 다시 만들어 연습했습니다.

이렇게 말하면 “과제 전체를 이해하고 있고, 내가 한 부분과 못한 부분을 구분해서 설명할 수 있다”는 인상을 줄 수 있어.
