Roscar 시스템 시나리오

### 🔹 시나리오 1. 직원의 요청에 따라 물건을 운반하는 경우

**상황**

매장 직원이 고객 요청 상품을 찾기 위해 Roscar에게 물건을 운반해달라고 요청함.

진행 흐름

직원은 시스템 화면에서 요청할 상품을 선택한다.

로봇은 자동으로 상품 위치로 이동한다.
이동 중 사람이나 장애물이 감지되면 안전하게 멈추거나 우회한다.

도착한 로봇은 물건을 정확히 찾아 들어 올린다.

요청된 장소로 운반한 후, 지정된 지점에서 멈추고 물건을 내려놓는다.

로봇은 작업을 완료하고 대기 장소로 이동하여 대기 또는 충전을 시작한다.

### 🔹 시나리오 2. 여러 로봇이 같은 장소에 접근하는 경우

**상황**

여러 직원이 동시에 요청한 상품의 위치가 비슷하거나 동일한 경우

진행 흐름

두 대 이상의 Roscar가 같은 장소로 향하려고 한다.

시스템은 자동으로 먼저 이동할 로봇을 결정하고, 다른 로봇은 잠시 대기한다.

먼저 도착한 로봇이 작업을 수행하고 물건을 운반한 뒤 이동한다.

대기 중이던 로봇이 그 뒤를 이어 작업을 수행한다.

### 🔹 시나리오 3. 로봇팔에 문제가 생긴 경우

**상황**

로봇이 물건 앞까지 도착했지만 집는 장치에 문제가 생김

진행 흐름

Roscar가 물건 앞에 도착했지만 물건을 들 수 없는 상태가 된다.

로봇은 작업이 불가능하다는 상태를 시스템에 자동으로 전달한다.

시스템은 다른 대기 중인 로봇을 선택해 남은 작업을 이어서 수행하게 한다.

문제가 생긴 로봇은 대기 장소로 복귀해 점검 대상이 된다.

### 🔹 시나리오 4. 직원이 직접 물건을 꺼낸 경우

**상황**

고객 응대를 위해 직원이 로봇 대신 직접 물건을 꺼내감

진행 흐름

직원이 상품을 직접 꺼내 고객에게 전달한다.

시스템은 사람에 의해 물건이 빠졌다는 것을 자동으로 감지하거나,
직원이 화면에서 처리 완료를 수동으로 등록한다.

재고 정보는 자동으로 최신 상태로 반영된다.

### 🔹 시나리오 5. 업무가 끝난 시간의 로봇 운영

**상황**

매장 영업 시간이 끝난 후, 로봇이 비업무 기능을 수행

진행 흐름

영업 종료 시간이 되면, Roscar는 순찰 또는 대기 모드로 자동 전환된다.

순찰 모드인 경우, 정해진 경로를 따라 매장 내부를 점검한다.

충전이 필요한 경우, 스스로 대기 장소(충전소)로 이동한다.

이 과정에서 위치 인식이나 정지 동작은 자동으로 수행된다.


# System Requirements 기반 시나리오

1. 재고 조회 및 작업 요청

 Staff는 신발 재고를 확인하고 배송을 요청하기 위해 Staff GUI를 사용한다. QR 인식을 수행하면 시스템은 서버의 데이터베이스를 조회하여 해당 신발의 모델명, 색상, 사이즈, 수량, Rack 위치 정보를 GUI에 표시한다.

 Staff는 표시된 재고 정보를 확인한 후 배송이 필요한 경우 [요청] 버튼을 클릭하여 작업을 요청한다. 요청 시 시스템은 현재 대기 큐 길이와 로봇 평균 작업 소요 시간을 기반으로 예상 대기 시간을 계산하여 GUI에 표시한다.

로봇의 가용성은 다음 두 조건을 모두 만족하는 경우로 판단된다:

로봇 상태: Idle

배터리 잔량: 20% 이상

조건을 만족하는 로봇이 있을 경우 작업이 즉시 배정되고, 로봇은 출발 준비를 시작한다.

2. 로봇 가용 불가 시 대기 큐 처리

 사용 가능한 로봇이 없을 경우 시스템은 요청을 **대기 큐(FIFO + 시간 우선순위)**에 등록한다. 이 큐에는 다음 정보가 저장된다:

요청 시간

출발지 및 목적지 좌표

신발 정보 (모델명, 색상, 사이즈)

Staff GUI에는 다음과 같은 메시지가 출력된다:

“현재 모든 로봇이 사용 중입니다. 요청이 대기 상태로 등록되었습니다. 로봇 사용 가능 시 자동으로 처리됩니다. 예상 대기 시간: 약 3분”

대기 큐에 등록된 작업은 요청 시간 기준으로 우선순위를 부여하며, 경과 시간에 따라 우선순위가 점진적으로 상승하는 방식이다.

로봇 상태는 ROS2 토픽 /roscar/status/battery, /roscar/status/state를 통해 수신된다. 시스템은 로봇이 Idle 상태로 전환된 순간, 배터리 조건을 함께 확인하고 대기 큐에서 우선순위가 가장 높은 작업을 자동 배정한다.

만약 작업이 **최대 허용 대기 시간(예: 10분)**을 초과하더라도 배정되지 않을 경우, 시스템은 Manager GUI에 "작업 요청 장기 대기 경고" 메시지를 전송한다.

3. 로봇의 목적지 이동 및 장애물 회피

 로봇은 출발지 또는 Rack 위치로 이동하기 위해 A* 기반 **전역 경로(Global Path)**를 생성하고 주행을 시작한다.

 이동 중 장애물을 감지할 경우 기존 경로를 폐기하고 DWB 기반 **로컬 회피 경로(Local Path)**를 
생성하여 우회한다.

장애물 감지는 다음 기준을 따른다:

LiDAR 기반 거리 측정 기준 (예: 0.5m 이내 물체)

감지 대상: 

고정 장애물 (Rack, 벽 등)

동적 장애물 (사람, roscar 등)

회피는 최대 3회 시도하며, 각 회피 경로는 장애물 감지 후 5초 이내에 생성되어야 한다.
다음과 같은 경우에는 회피 실패로 간주한다:

회피 경로 생성 실패 (DWB 출력 없음)

회피 실행 중 위치 변화가 없는 경우(지속 정체)

 3회 모두 실패할 경우 **Global Planner에게 전역 경로 재계산(Global Replan)**을 요청한다.
그 이후에도 로봇이 20초 이상 정지 상태를 유지할 경우 시스템은 Manager GUI에 정체 알림을 전송한다. 관리자는 상황을 확인하고 수동 개입할 수 있다.

4. 정밀 정차 및 픽업

 로봇이 Rack 근처에 도달하면 ArUco 마커 인식을 통해 정밀 정차를 시도한다.
만약 마커를 인식하지 못하면 로봇은 제자리 회전을 하며 인식을 시도하지만 10초 내 마커 인식 실패 시 로봇은 최대 2회까지 제자리 회전을 수행하며 추가 인식을 시도한다. 이후에도 실패 시 아래와 같이 처리한다:

시스템은 “정밀 정차 실패” 경고를 Manager GUI에 전송

로봇은 후속 명령 대기 상태로 전환되어 관리자의 수동 지시를 대기

마커 인식 후 정차가 완료되면 로봇은 신발 픽업을 시도한다. 수레 하단에 장착된 압력 센서를 통해 물체 감지를 수행하고 감지되면 픽업 성공으로 간주하며 재고 수량을 실시간 차감한다.

만약 압력 센서가 고장 또는 미감지 상태일 경우 다음과 같이 처리한다:

시스템은 “픽업 실패 가능성” 경고를 GUI 및 Manager에게 전송

재고 차감은 일시 보류되며 관리자 수동 확인 또는 재시도 필요

픽업이 성공적으로 감지되면 Staff GUI의 요청 취소 버튼은 비활성화된다.

5. 배송 및 상태 모니터링

픽업 완료 후 로봇은 A* 경로를 따라 목적지로 배송을 수행한다.
배송 중 상태는 다음과 같이 실시간 표시된다:

Staff GUI: “배송 중” 상태 및 요청 정보

Manager GUI: 로봇 위치, 배터리, 주행 상태 등 주기적 갱신

 장애물 회피 실패, 경로 오류, 센서 이상 등의 이슈 발생 시 즉시 Manager GUI에 경고 알림이 표시된다.
관리자는 실시간 상황을 모니터링하고 필요시 수동 개입할 수 있다.

 도착 시 “도착” 상태로 표시되고, 물품 인도가 완료되면 “픽업 완료”로 전환된다.

6. 작업 완료 후 대기 장소 이동

 로봇은 작업 완료 후 대기 장소로 이동하기 위해 A* 알고리즘을 기반으로 경로를 생성한다.

대기 장소 도착 후 로봇은 Idle 상태로 전환되며, 이후 새로운 작업 요청에 응답할 준비를 한다

# User Requirements 기반 시나리오


Roscar 시스템 운영 시나리오

🔹 시나리오 1: 직원이 상품 배송 요청 → Roscar 수행 → 대기장소 복귀

목표: 매장 직원이 특정 상품을 요청하면, Roscar가 이를 집품하여 지정 위치로 배송하고, 이후 대기 장소(=충전소)로 복귀

1단계: 상품 요청 발생

매장 직원이 상품 박스의 QR 태그를 스캔함 (→ UR_12)

Main Server는 해당 상품 정보 및 요청 위치를 파악하고, 작업을 큐에 등록함 (→ UR_04, UR_09)

2단계: 작업 가능한 Roscar 선정

Main Server는 현재 상태를 실시간 수신한 Roscar들 중,

충전 중이 아닌 Roscar (→ UR_16)

가장 가까운 거리 또는 대기 중인 Roscar (→ UR_30, UR_08-1)
를 선정해 해당 작업을 할당함

3단계: Roscar 이동 및 상품 인식

Roscar는 자율주행하여 지정된 rack(Rack) 위치로 이동 (→ UR_01, UR_06)

이동 중 사람과의 충돌 방지를 위해 사람을 감지하면 정지 또는 회피 (→ UR_05)

도착 후 로봇팔이 해당 상품을 정확히 인식하고 (→ UR_20), 안정적으로 집어 올림 (→ UR_21)

4단계: 적재 및 배송 수행

로봇팔이 박스를 적재 공간에 안전하게 싣고 (→ UR_26)

지정된 배송 위치(예: 출고지점)로 이동 후 정확히 정지 (→ UR_11)

적재된 상품을 지정 위치에 내려놓음

Main Server는 해당 배송 내역을 재고 시스템에 자동 반영 (→ UR_22, UR_03)

5단계: 대기 장소 복귀 및 충전

작업 완료 후, Roscar는 ArUco 마커 기반 위치 보정을 통해 (→ UR_12-1)
**대기 장소(=충전소)**로 복귀하고 충전을 시작 (→ UR_16)

🔹 시나리오 2: 동일 위치에 2대 이상의 Roscar가 접근

목표: 동일한 rack 위치에 여러 Roscar가 접근할 경우, 충돌 없이 안전하게 작업 수행

1단계: 작업 충돌 상황 감지

2단계: Main Server의 우선 접근 제어

먼저 요청된 작업

3단계: Roscar A가 작업 수행 후 복귀

Roscar A가 상품 인식 및 적재 후 이동

완료 시 Main Server는 대기 중인 Roscar B에게 다음 작업을 할당

🔹 시나리오 3: 로봇팔 장애 → 작업 재할당

목표: Roscar A의 로봇팔이 고장나 작업 불가 → 다른 Roscar에게 작업 재할당

1단계: 고장 감지

# Manager GUI 타당성


Manager GUI의 필요성

Staff 겸임의 한계

고객 응대/작업에 집중해야 하므로 즉각 대응이 어려움

시스템 전반의 모니터링 및 통제는 관리자 책임

위험 상황 통제 권한 분리 필요

작업 취소, 수동 복귀 등 권한 분리로 안전 확보

예외 상황 대응

Task 자동 실패, 충돌 발생 등 상황에서 판단 및 조치 주체 필요

Manager GUI는 단순 시각화 도구가 아니라 현장 통제의 인터페이스다.
