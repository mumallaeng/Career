## 확인 목적

로봇 운용 중 충돌 위험, 사람 접근, 시스템 오류 등 긴급 상황 발생 시 즉시 정지(Emergency Stop)하고, 사용자의 명시적 복구 요청 또는 조건 충족 시 기존 작업을 안전하게 이어서 수행할 수 있는 구조를 설계한다.
본 기능은 로봇 운용의 안전성과 연속성 확보에 핵심적인 요소이다.

---

## 주요 조사 항목

| 항목명            | 조사 내용                                                                                                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 긴급 정지 트리거 방식   | 수동 트리거: GUI 버튼, 물리 버튼, 키 입력, 리모컨 등<br>자동 트리거: 감지 거리 임계치 이하, 센서 오류, 시스템 예외 상황 등<br>ROS 예시:<br>/roscar/emergency/state 명령<br>/alert/emergency/admin 보고                   |
| 정지 동작 처리 방식    | 현재 Goal 전체 취소 → navigate_to_pose 상태 = CANCELED 또는 ABORTED<br>로봇 속도 강제 0 고정 → cmd_vel = (0.0, 0.0)<br>FSM·BT 기준 상태 전환: EMERGENCY_STOP                                   |
| 정지 후 시스템 유지 상태 | 경로 계획 중단, 속도 고정 상태 유지<br>복구 신호 수신 전까지 Idle 또는 Stopped 상태 유지<br>/roscar/status/log 또는 UI에 “비상 정지” 상태 표시 필요                                                              |
| 복구 기능 트리거 방식   | 수동 복구: GUI의 “복구” 버튼 클릭<br>자동 복구: 감지된 장애물 제거 등 사전 정의된 조건 충족 시<br>ROS 예시:<br>/roscar/emergency/state → command = 0x01 (재시작)                                              |
| 복구 후 동작 흐름     | FSM·BT 상태를 PREVIOUS_TASK로 복귀 가능<br>이전 Goal 재전송 또는 새로운 Goal 대기 상태 전환<br>로그 예시:<br>[bt_navigator]: Resuming task from emergency stop.                                    |
| 테스트 시나리오       | /roscar/emergency/state 명령 전송 후 즉시 정지 여부 확인<br>복구 전 Goal 재전송 시 무시되는지 확인<br>/roscar/emergency/state (재시작 명령) 전송 후 기존 또는 신규 작업 재개 여부 확인<br>로그, 속도, 상태 전이 흐름에 대한 정밀 검증 필수 |
