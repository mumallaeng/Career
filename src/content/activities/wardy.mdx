## 설계

### M-02 익명 추적

M-03·M-04는 한 사람의 자세를 몇 초간 이어 붙여 봐야 하므로, 프레임 사이를 연결하는 임시 `track_id`가 필요하다. SORT의 Kalman Filter + IoU Gate + Hungarian Matching 조합(M-02A)을 기본으로 만들고, IoU·중심 이동량·크기 변화를 입력받아 같은 사람인지를 매칭 비용으로 직접 내는 MLP(M-02B)를 함께 만들어 비교했다. 매칭이 10프레임 이상 끊긴 track은 소멸시키고, 매칭되지 않은 detection은 새 track으로 등록한다.

<ImgTag filename="wardy-readme-28.png" alt="M-02 추적 구조" />

그림 2. M-02 추적 구조

### M-03 자세 추정

M-02가 넘긴 사람 영역을 1.25배 넓혀 192×256으로 변환하고, RTMPose로 COCO-17 관절을 추정한 뒤 관절 벡터의 각도와 비율로 standing·sitting·lying·unknown을 판정한다. 처음에는 경량인 RTMPose-t를 썼지만 실물 시험에서 포즈 출력이 사라지는 경우가 있어 RTMPose-M으로 바꾸고, 관절이 일부만 잡힌 결과는 버리도록 했다. 판정 규칙도 실물 시험을 거치며 아래처럼 바꿨다.

| 판정 항목 | 처음 | 수정 후 |
|---|---|---|
| 누워 있음 | abs(dx) ≥ abs(dy) × 0.85 | abs(dx) > abs(dy) × 1.20 (수평에 더 가까운 몸통만) |
| 앉아 있음 | hip_to_knee_y &lt; torso × 0.65 | 평균 무릎 각도 145° 미만, 145°\~155° 완충 구간은 거리 비율 0.50 fallback |
| 서 있음 | 위 두 조건이 아님 | 평균 무릎 각도 155° 이상 |
| 시간축 | 없음 | 최근 5프레임 다수결 |

### M-04 낙상 감지

일상적인 눕기와 실제 낙상을 구분하려면 같은 사람의 자세 변화를 시간축으로 봐야 한다. track별로 최근 20프레임(2초)의 pose를 순환 버퍼에 쌓고, 두 경로로 판단한다.

- **Fast Path:** 직전 두 프레임이 연속 standing이다가 이번 프레임에 lying이면, 윈도우가 차기를 기다리지 않고 바로 낙상 후보를 만든다.
- **TemporalFallGRU:** 윈도우가 차면 20프레임을 75차원 특징 시퀀스로 바꿔 z-score 정규화한 뒤 단방향 GRU로 낙상 confidence를 낸다. URFD 데이터셋에서 추출한 관절 시퀀스로 직접 학습했다.

confidence가 threshold 이상이면 낙상 의심으로 판정한다. threshold는 재학습으로 실수로 낮아지지 않도록 코드에 60% 하한을 고정했다.

## 구현

- **Python 추론 Runtime:** `TrackingPoseFallRuntime` 하나에서 M-02 → M-03 → M-04를 track별로 이어 실행하고, 낙상 확률과 의심 결과를 C++ 서비스로 돌려준다.
- **Edge 연동:** M-01 사람 탐지 결과를 pose_fall_worker로 넘기는 경로와 M-01\~M-05 추론 결과를 Runtime에 연결하는 작업을 맡았다. 낙상 이벤트와 돌봄 상태가 공통 이벤트 계약을 따르도록 맞췄다.
- **UI·운영:** 브라우저 모니터링 UI를 TypeScript로 옮기고, Jetson V4L2 카메라 입력, 카메라 자동 재연결, systemd 자동 시작, Hugging Face 모델 버전 고정 배포를 구성했다.

## 문제 해결

### 긴급 상태가 고정되거나 바로 풀림

- **증상:** 서 있거나 앉아 있어도 돌봄 상태가 긴급으로 고정되거나, 반대로 낙상을 인식해도 다음 프레임에서 바로 해제됐다.
- **원인:** 자세 판정이 흔들리면 그 위의 낙상 판단도 흔들렸고, 상태 전이 로직이 잘못 바뀐 상태를 그대로 고정했다. 두 문제가 겹쳐 나타났다.
- **수정:** 낙상 사건을 latch해 사용자가 확인하거나 오탐으로 처리할 때까지 유지하고, 자세가 더 이상 낙상 의심이 아니면 스스로 해제되도록 했다. 낙상 사건은 lying 자세일 때만 남기도록 게이트를 넣었다.

### 낙상을 놓치는 회귀

- **증상:** 08-14에 누워 있음 판정 기준을 엄격하게 고친 뒤 오히려 낙상을 인식하지 못했다.
- **원인:** 엄격해진 lying 기준을 넘지 못한 낙상 동작이 정상 자세로 판정돼 M-04까지 이어지지 않았다.
- **수정:** 포즈 판정에 낙상 의심 상태를 추가해, 의심 단계에서 낙상 확인이나 오탐 처리를 할 수 있게 구조를 바꿨다.

### 추론 지연 중 끊기는 낙상 이력

- **증상:** Jetson 추론이 늦어지거나 M-01이 사람을 한 프레임 놓치면, 진행 중이던 낙상 판단이 처음부터 다시 시작됐다.
- **원인:** track의 pose 이력이 프레임 공백에서 끊겨, M-04가 20프레임 윈도우를 채우지 못했다.
- **수정:** 일정 시간 안의 공백이면 track의 낙상 이력을 유지하고, 그 시간을 넘으면 버리도록 바꿨다. 유지와 만료 두 경우를 테스트로 확인했다.

### 상체만 보일 때의 오탐

- **증상:** 상체만 보이는 상황에서 낙상 오탐이 잦았다.
- **원인:** M-03 자세 오탐이 M-04 낙상 판단으로 그대로 이어졌다.
- **수정:** 성공 사례와 오탐 사례 데이터를 함께 쌓아 M-03 판정 기준을 다시 조정하고, 관절이 일부만 잡힌 결과는 버렸다. 운영 threshold도 60%로 올렸다.

## 배운 점

- 모듈마다 테스트 데이터에서는 잘 됐는데, 통합하고 실제로 넘어져 보니 문제는 모듈 사이의 경계에서 나왔다. 자세가 한 번 흔들리면 낙상 판단과 상태 표시까지 줄줄이 흔들려서, 모듈 하나의 정확도보다 앞단 결과가 끊기거나 틀릴 때 뒷단이 어떻게 버티는지를 먼저 설계해야 한다고 느꼈다.
- 추적기는 학습 기반인 MLP 쪽도 만들어 비교했는데, 지표 네 개를 나란히 놓고 보니 단순한 SORT 계열이 모든 지표에서 앞섰다. 더 복잡한 방법이 더 낫다고 가정하지 않고 직접 재서 고르는 게 맞았다.
- 처음 접한 추적·자세 추정·시계열 분야였지만, 원리를 이해한 뒤에는 실물 시험 결과를 보고 판정 규칙을 어디서 고쳐야 할지 스스로 정할 수 있었다.
