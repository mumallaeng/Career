> *(KDT) ROS2와 인공지능을 활용한 자율주행 로봇 개발자 양성과정 8기* 교육과정 내에서 진행된 파이널 과제입니다. 3팀 **Secondary Wave**는 본 프로젝트로 최종 발표회에서 최우수상(1위)을 수상하였습니다.

<DriveAssetGrid actId="Shoepernoma" layout={[33, 66]} end={2} />

매장 연동형 자율주행 로봇을 활용해 신발 상자를 자동으로 피킹(Picking)하고 전달하는 스마트 물류 솔루션입니다.
- 오프라인 매장 내 물류 처리 자동화 및 효율화
- ROS2 기반 자율주행 로봇 개발 및 AI 영상 처리 기술 적용
- GUI 연동으로 실시간 재고 관리 및 피킹 요청 처리

LiDAR+IMU 기반 2D SLAM(Cartographer)으로 지도를 작성하고 자율주행에는 Nav2이 사용되었습니다. \
OpenCV ArUco Marker를 활용해 주행 초기 위치 보정과 근접 정렬·도킹 기능을 구현했습니다. \
YOLOv8n 모델로 신발 상자 객체 인식을 수행하고, Python 기반 GUI로 로봇 상태 및 재고 현황을 실시간으로 모니터링할 수 있습니다.

## 담당 역할

- **설계 대상:** 팀장으로서 Main Server의 `main_service`(ROS2 Action·Service·Topic), 피킹 요청을 로봇 작업으로 바꾸는 작업 할당 흐름, 시퀀스 다이어그램 기반 DB 구조와 ORM, AI 서버(TCP/UDP) 연동, rack·cart·arm controller
- **목적:** 주행·인식·GUI를 각자 맡은 4개 파트가 '직원 요청 → 재고 확인 → 로봇 배차 → 픽업 → 전달'이라는 하나의 흐름으로 이어지게 만드는 것
- **검증 방식:** 인터페이스 명세와 시퀀스 다이어그램에 맞춰 메시지·쿼리를 정의하고, 기능별 테스트 케이스(주행·정차·객체 인식)와 최종 통합 시연으로 확인

| 파트 | 한 일 |
|:--|:--|
| `main_service` | ROS 노드 구조 초기화, Manager GUI와의 Service·Topic 연결, 로그 조회 Service와 이벤트 publish, 제어 명령 publisher |
| 작업 할당 | 재고 요청 처리(`handle_inventory_request`), `StartDelivery` Action client로 작업 요청·응답, mobile_controller의 Action 실행 지원 |
| DB | 시퀀스 다이어그램 기준 테이블·쿼리 정의, ORM, SSL 연결 설정, seed 데이터, 로그 DB |
| AI 서버 연동 | Object Detector·FileSystem 이벤트·TCP/UDP 통신을 Main Server에 연결 |
| 컨트롤러 | `rack_controller`·`cart_controller` 패키지, 모터 드라이버로 서보 각도를 주는 `roscar_arm_controller` |
| 구조 정리 | monorepo 패키지 구조, 이름 통일(Robot → Roscar), 빌드·실행 스크립트 |

## 설계

### 시스템 구조

Main Server가 직원용 단말, Manager GUI, AI 서버, 여러 대의 Roscar 사이에 서서 요청을 받고 작업을 나눈다. 단말과 서버 사이는 TCP, 영상은 UDP, 서버와 로봇 사이는 ROS2로 정리했다. 요청·응답은 인터페이스 명세의 메시지 코드(인증, 재고 검색, 재고 요청, 작업 알림 `TR_NOTIFY` 등)로 고정해, 파트별 구현이 바뀌어도 경계가 흔들리지 않게 했다.

### 작업 할당 흐름

직원이 재고를 요청하면 `main_service`가 DB에서 재고와 위치를 확인하고 작업을 만든 뒤, `StartDelivery` Action으로 로봇에 작업을 보낸다. 작업 요청과 응답은 Action으로 주고받고, 이벤트는 Topic으로 publish해 Manager GUI가 받으며, 로그는 ROS Service로 조회한다. 흐름별로 시퀀스 다이어그램을 먼저 그리고, 다이어그램의 메시지와 쿼리를 그대로 코드로 옮겼다.

## 구현

- **`main_service`:** ROS 노드, DB 접근, AI 서버 통신, GUI 연동을 내부 패키지로 나눠 다시 배치하고, Manager GUI와 모듈 경계를 분리했다.
- **컨트롤러:** rack·cart 제어는 PlatformIO 기반 MCU 패키지로, 로봇 암은 모터 드라이버로 서보 각도를 주는 패키지로 만들었다.
- **빌드:** `build.sh`·`roscars.sh`로 서버·AI 모듈·로봇 노드를 한 번에 띄우도록 정리했다.

## 검증·결과

- 기능별 테스트 케이스(대기 장소 이동, 지정 랙 이동, 정밀 정차, 객체 탐지 후 정지 등)를 Confluence 양식으로 관리했다. [테스트 문서](shoepernoma/test.md)
- 최종 시연에서 직원 단말의 재고 요청부터 로봇 배차, 랙 픽업, 전달까지 한 흐름으로 동작했고, 최종 발표회에서 최우수상(1위)을 받았다.

## 배운 점

- 4개 파트가 각자 잘 돌아가도, 메시지 이름 하나나 쿼리 하나가 어긋나면 전체 시연이 멈췄다. 시퀀스 다이어그램을 먼저 그리고 거기에 맞춰 코드를 짜는 방식이 통합 단계의 충돌을 가장 많이 줄여 줬다.
- 팀장으로 구조를 잡으면서, 코드를 직접 많이 짜는 것보다 모두가 같은 이름과 같은 경계를 쓰게 만드는 일이 일정에 더 큰 영향을 준다는 걸 배웠다.
